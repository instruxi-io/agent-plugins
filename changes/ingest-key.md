- Telemetry-only ingest keys for harnesses that take a fixed OTLP header (Codex, Gemini CLI, Hermes, OpenClaw): `src/ingest-key.mjs` (`ensureIngestKey({harness})`, `ingestHeaders(harness)`, `INGEST_SCOPE` = `governance:ingest`, `OTLP_BASE(baseUrl)`) and `enforcer ingest-key --harness <h> [--json]` find or create a v3 agent `<harness>@<hostname>` under the signed-in account and issue it a credential carrying `governance:ingest` alone with the harness on the credential, cached per harness in `~/.enforcer/ingest-keys.json` (0600, atomic). The key is checked with v3 at most hourly, replaced by a freshly issued one with under 7 days left (the old one expires on its own; no rotate/revoke, so no `.destructive` scope), minted again when revoked, and never replaced when the agent is disabled in the console (the off switch); at most two live keys per harness. The default browser sign-in (`work`, and `plan`) now asks for `enforcer:agents.write` and `enforcer:agents-credentials.write` so the plugin can provision these keys without a second consent; an older sign-in gets `insufficient_scope` (CLI exit 5) telling it to log in again. CLI exit codes: 0 ok, 1 failed, 2 usage, 3 signed out, 4 agent disabled, 5 log in again.
